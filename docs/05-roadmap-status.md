# 迭代路线图执行状态（基于 docs/04 竞品分析）

记录 04 竞品分析里那张路线图的**实际落地情况**：哪些已做、哪些刻意没做及原因。诚实第一。

## ✅ 已实现（P0 / P1 / P2 中可端上落地的部分）

| 项 | 优先级 | 状态 | 实现位置 |
|---|---|---|---|
| **边缘 matting 精修** | P0 | ✅ 已做 | `FloatImage.guidedRefined`（guided filter，用 RGB 亮度引导把主体 mask 贴合图像边缘），管线在分割后调用。改善发丝/半透明边、减少漏光与补全掩膜脏 |
| **N 层 LDI / MPI 渲染** | P0 | ✅ 已做 | `Shaders.metal` 的 `mpi_fragment` + `ParallaxRenderer` 多 pass：补全背景 base + N 个深度带(tent 隶属度) back-to-front over 合成。UI "分层(LDI)" 步进器 1–6，默认 4；=1 退化为原 2 层快速路径。**直接针对"大角度拉伸"** |
| **tiled / 裁剪 LaMa 提分辨率** | P1 | ✅ 已做 | `LamaInpainter` 按洞包围盒(+留边上下文)裁剪后再喂 512 模型，让洞接近原生分辨率（单次推理即显著提清晰度），而非把整张压到 512 |
| **深度 Base 质量档（插槽）** | P1 | ✅ 插槽已留 | `DepthEstimator.modelCandidates` 优先 `DepthAnythingV2BaseF16`，缺失自动回退官方 Small。放入 Base 的 Core ML 包即自动启用（高端机更高深度精度） |
| **运动轨迹视频导出（收敛幅度）** | P2 | ◐ 部分 | `VideoExporter` 改用幅度收敛的水平为主 figure-8，减少极端机位拉伸暴露。完整的"显著性感知最小拉伸轨迹优化"留作后续 |

## ❌ 刻意未做（诚实说明，不塞假实现）

| 项 | 优先级 | 为什么不做 |
|---|---|---|
| **Flash3D 式端上前馈 3DGS（Premium）** | P3 | **端上不可行**，这是竞品分析自己的结论：Flash3D 依赖 UniDepth 基座 **800MB–2GB**，每帧数亿次高斯运算，**研究界至今没有移动版**，推理是瓶颈（不是渲染——渲染有 MetalSplatter 现成）。塞一个跑不起来的壳是欺骗。**预留路径**：若将来出现可端上的单图→3DGS 蒸馏模型，渲染层直接接 `scier/MetalSplatter`(MIT) 即可，表示法是高端机付费差异化档，不进主线 |
| **服务端"电影级回放"扩散模式** | P3 | 需要服务端，**破坏本项目 100% 离线/隐私的核心叙事**。如要做，应作为明确可选的云增值，而非默认 |
| 显著性感知轨迹优化 / 时序视频管线 | P2 | 价值有限且复杂，优先级低于 P0/P1 |

## 验证边界（重要）

- **已验证**：以上 ✅ 项全部**编译通过、模拟器运行不崩、逻辑正确**（含 Swift/Metal uniform 一致性、MPI 多 pass 合成、裁剪 LaMa I/O）。
- **未能在此验证**：**画质改善的实际效果**——因为 ① 模拟器跑不了真分割（`VNGenerateForegroundInstanceMask`），② 内置合成示例图对 LaMa 是分布外输入。**N 层 LDI 对大角度的改善、裁剪 LaMa 的清晰度、边缘精修的效果，都需在真机用真实照片确认。** 建议把"分层"在 1（旧 2 层）与 4（新 MPI）之间 A/B 对比，反馈截图后继续调参。

## 核心原则

守住"**端上 + 实时 + 任意机型 + 离线隐私**"这块没人能同时占住的高地；不动表示法的根（分层/2.5D），把层数、补全分辨率、边缘质量逐项补上去。3DGS 只作为将来高端机的可选差异化档。
