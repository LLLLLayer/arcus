# 10 · 前景剪影抗锯齿（matte 边缘毛刺的定位与修复）

> 用户反馈：「分层（裁剪主体）时，边缘有很多毛刺/锯齿。」
> 本文记录**如何一步步定位真因**、每一轮改了什么、为什么，以及在真机上的验证方法。
> 结论：锯齿有**三个叠加来源**，需要三层修复；其中**真正的根**是分割 mask 的低分辨率边界，必须在管线里把它重新「吸附 / 磨平」，而不是只在着色器里抗锯齿。

---

## 0. 现象

前景主体被抠出后，沿剪影有阶梯状毛刺，倾斜/拖动（视差）和前景放大（`fgScale`）时更明显。

## 1. 定位过程（三轮，逐步逼近真因）

### 第 1 轮：以为是着色器抗锯齿不够 → 发现 MSAA 的认知误区

读 `Shaders.metal` + `ParallaxRenderer.swift` 发现：

- 片元里前景剪影用的是**固定阈值** `smoothstep(0.44, 0.56, c.a)`；
- 渲染开了 **4× MSAA**，注释写「几何抗锯齿交给 4×MSAA」。

**关键误区**：MSAA 只对**几何边**（前景网格被切开的「切口」）抗锯齿；它**对「matte alpha 阈值」这条真正的剪影无效**——前景四边形内部 4 个子样本采到的 alpha 几乎一致，MSAA 给不了亚像素覆盖。于是剪影的抗锯齿其实**只**依赖那条固定的窄 smoothstep 带，且 matte 在管线里被硬收紧到近二值（`smoothStep(0.46, 0.54)`），等于把锯齿原样画出来。

→ **第 1 轮修复**：
- 片元改 **解析抗锯齿**：用屏幕空间导数 `fwidth(c.a)` 自适应阈宽，剪影恒得 ~1px 软覆盖；
- 管线把 matte 收口放宽 `0.46–0.54 → 0.42–0.58`，给 AA 留梯度。

正常视图边缘变软，但**用户反馈仍有锯齿**。

### 第 2 轮：上真机截图，调出「主体」调试图层 → 看见 matte 本身的粗台阶

用 iVista 连真机，跑 App → 切到底部 **「主体」调试图层**（`debugMode==2`，片元直接输出 `c.a`，即原始 matte），再用 ImageMagick 把剪影裁切放大 5–6×：

> **matte 边界是一条很粗的像素台阶（~10px 锯齿）。**

这解释了为什么第 1 轮不够：`fwidth` 抗锯齿只能软化过渡的「**厚度**」，**扶不直台阶的「走向**」。台阶的来源是 **Vision 实例分割 mask 是低分辨率生成、再上采样**来的——边界天生是块状的；而原来的 guided filter 半径太小（`W/200`≈7px）跨不过台阶、`eps` 极小又保留了它。

→ **第 2 轮修复**：把边缘精修换成 **joint-bilateral 式 guided upsampling**——把 guided 半径放大到能跨过台阶块（`W/110`≈14px），强 `eps` 把边界**吸附到全分辨率亮度边缘**；再加一遍小低通 + 收口。
真机复测：示例图（高对比橙球）的 matte 台阶**消失**，正常渲染丝滑。

### 第 3 轮：低对比处仍有台阶 → 单亮度引导吸不住，改用 RGB 彩色引导

用户复测：「效果变好了，还有一点点。」进一步确认是**低对比处**（浅灰杯 + 浅灰墙）的残余台阶。

原因：第 2 轮用**亮度**做引导。浅灰杯和浅灰墙**亮度几乎相同**，亮度梯度≈0 → guided 吸不住边 → 那里只剩台阶。

→ **第 3 轮修复**：实现 **RGB 三通道彩色 guided filter**（`FloatImage.guidedRefinedColor`，He et al. matting 版，每像素解 3×3 协方差系统）。它能利用**色差**（亮度相近但颜色不同）吸边；在**真的无边**的平坦区 `a→0`，自动退化为局部均值 → 把低分辨率台阶磨成平滑斜坡（即「自适应再磨平」）。所以它**只会更好、不会更糟**。
真机复测：高对比橙球**无回退**，仍干净。

## 2. 最终的三层修复（叠加）

| 层 | 文件 | 改动 | 作用 |
|---|---|---|---|
| ① 片元解析 AA | `Arcus/Rendering/Shaders.metal` | `aa = fwidth(c.a)*0.7` 驱动 `smoothstep(0.5-aa, 0.5+aa, c.a)`，取代固定 `0.44–0.56` | 剪影恒 ~1px 软覆盖，随缩放自适应；修过渡「厚度」 |
| ② matte 收口放宽 | `Arcus/Pipeline/Photo3DPipeline.swift` | `smoothStep(0.46,0.54) → (0.42,0.58)`（中点仍 0.5 ⇒ 剪影不移、不漏光） | 给 ① 留梯度，避免近二值阶梯 |
| ③ 边界重吸附（根） | `Photo3DPipeline.swift` + `Arcus/Core/FloatImage.swift` | **RGB 彩色 guided upsampling**（`guidedRefinedColor`, 半径 `W/130`, `eps 1e-4`）+ 小低通(`boxBlurred W/360`) + 收口 | 把低分辨率 mask 台阶吸到真实边缘 / 平坦区磨平；修台阶「走向」 |

> `guidedRefinedColor` 用 O(n) 滑窗均值（`boxMean`）求各阶矩，半径取大也不变慢；一次性管线开销可忽略。

## 3. 关键洞察（可复用的经验）

1. **MSAA ≠ alpha 剪影抗锯齿**。alpha-test/阈值边缘要么用 `fwidth` 解析 AA，要么用 alpha-to-coverage（但后者与预乘 over 混合会双重压暗，本项目不用）。
2. **抗锯齿分两件事**：过渡「厚度」（片元 `fwidth` 解决）和边界「走向」（必须在生成 matte 时解决）。只做前者治标。
3. **分割 mask 是低分辨率的**：要得到高分辨率干净剪影，本质是「**引导式上采样**」——用全分辨率原图把 mask 边界吸附到真实边缘（guided / joint-bilateral）。半径要 ≥ 台阶块尺寸才能跨过它。
4. **低对比要用彩色引导**：亮度相近时色差才是边；彩色 guided 严格强于亮度 guided，且无边处自动退化为平滑。
5. **物理下限**：若主体与背景**亮度、颜色都一致**，图里根本没有边，任何吸附都无能为力，只能靠平滑做到「软而不锯齿」。这种极端情况少见。

## 4. 真机验证方法（本次用的流程）

1. iVista 启 WDA：`ivista wda start --device <udid> --auto-port`；
2. `AUTOSAMPLE=1 DEBUGMODE=2` 启动直接处理示例图并停在「主体」matte 图层：
   `xcrun devicectl device process launch --environment-variables '{"AUTOSAMPLE":"1","DEBUGMODE":"2"}'`；
3. `ivista observe --json` 拿截图；ImageMagick 裁剪剪影并 5–6× 放大（NEAREST）：
   `magick shot.png -crop WxH+X+Y +repage -filter point -resize 600% out.png`；
4. 对比「主体」原始 matte 边界 与 「正常」渲染边界——前者暴露台阶根因，后者看最终观感。

## 5. 仍可推进（按需）

- 若极低对比处仍有残留：对**局部梯度低**的区域自适应加大平滑半径（有边处不动）；
- 发丝级 alpha：上一个轻量 matting 精修模型（trimap/guided matting net）——属于「加模型」，端侧成本更高，非必要不做。
